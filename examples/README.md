# Examples from the fictional Rootline data

Rootline is a **made up** carbon accounting company for food and beverage producers. Everything here, including every customer, quote and number, is fictional. It exists so the process could be built, measured against an answer key, and shared.

| File | What it shows |
|---|---|
| `rootline-asset-excerpt-OP-2.md` | The start of one enablement asset (a one page business case), with its header block |
| `rootline-asset-register-sample.csv` | The first rows of the asset register |
| `rootline-claims-sample.csv` | The first claims, with scope, era and which assets carry them |
| `rootline-claim-links-sample.csv` | Which asset sections carry each claim |
| `rootline-transcript-excerpt.md` | The start of one call transcript, in the format the readers expect |
| `rootline-reader-output-sample.csv` | A dozen rows a reader wrote from a call |
| `rootline-labels-sample.csv` | The start of the labels list |
| `rootline-report-first-screen.md` | The first screen of the report after three weeks |
| `rootline-vehicles-by-stage.svg` | The visual of assets by buying stage |
| `rootline-asset-heatmap.svg` | The visual of asset use week over week |

Use them to see what *your* files should look like. Do not copy the content.

## Review examples (from week 34 of the fictional run)

| File | What it shows |
|---|---|
| `rootline-retro-example.md` | A retro: what ran, the numbers against the week before, findings tagged fix now, watch and no change, and the decisions that needed the owner |
| `rootline-spot-check-example.md` | A spot check: ten adjudicated items, with the claim, the ruling and the words |
| `rootline-spot-check-rulings-example.md` | The owner's rulings on that spot check, mapped to each item |
| `rootline-label-review-example.md` | A label review: the labels still open after the owner ruled on the first ten |

Names like "Victor" and "you" appear in these because they are real working files. Read them for the shape of each review.
